# Automated Phishing Detection for Frontier AI Inference

**Status:** Prepared for advisor review. I have not run the proposed experiments or accessed any PhishVN test records or results.

**Version:** 1.0 | **Date:** 2026-08-16

## Proposed Study Plan

### Threat model

The unit of analysis is one raw URL carried through model input, retrieval or tool context, or model output at a frontier-AI inference gateway. An adversary may choose the URL string and vary its domain and character composition, while phishing campaigns can also change over time. The detector observes only the raw URL and features derived from it. It does not fetch the URL, inspect the destination page, use DNS or WHOIS lookups, or inspect private request content.

The security objective is to identify phishing URLs at a low false-positive operating point while preserving gateway performance. For schema-valid requests, the gateway returns an `allow` or `alert` decision. It sends uncertain requests, and requests observed during a detected shift, to the second-stage model; it does not perform automatic blocking, takedown, or other remediation. Schema-invalid requests follow the frozen FastAPI validation behavior and are not relabeled as phishing.

### Problem and thesis

Random row splits can overstate URL-classification performance when related domains occur in both training and test data, and a single fixed model may not remain reliable under temporal or domain shift. Running a transformer for every request may improve representation capacity but impose unnecessary operational cost.

I will test three linked claims. First, whether structural URL features and a compact character-level transformer improve low-FPR recall across domain-disjoint and external source/domain evaluation. Second, whether unsupervised shift monitoring can identify when broader transformer use is warranted. Third, whether selective execution can remain within two percentage points of transformer-only recall while meeting the stated invocation, latency, and error targets. These claims are prospective and will be evaluated under the decision rules below.

## Proposed Method and Evidence

| Element | Specification |
|---|---|
| Development data | Public, licensed PhiUSIIL data, split 70/15/15 by registrable-domain group into train, validation, and test partitions with seed `20260816`. A registrable domain may appear in only one partition. |
| External confirmation | The provided PhishVN group-aware temporal split remains sealed until written approval and protocol freeze. Its full published test order is used for monitoring, `gold` records are primary for detection-error inference, and `all` records are a prespecified sensitivity analysis. Frozen detection models are scored without refitting or recalibration. |
| Detection models | Stage 1 is `Logistic-L1` on length/structure, character composition/entropy, authority syntax, and path/query features. Stage 2 is a compact character transformer over an IDNA-normalized ASCII URL and a fixed, training-derived character vocabulary. Input is capped at 256 characters by retaining the first 192 and last 64. The encoder has 4 layers, width 192, 6 attention heads, feed-forward width 768, and dropout 0.1. Training uses weighted binary cross-entropy, AdamW, and early stopping on validation average precision. Seed `42` is primary; seeds `42`, `43`, `44`, `45`, and `46` form the sensitivity analysis. Random Forest remains a secondary benchmark and does not determine a hypothesis decision. |
| Calibration | Preprocessing is fitted on training data, and model selection is completed without test access. On validation data only, each model threshold maximizes recall subject to the exact one-sided 95% Clopper-Pearson FPR upper bound being <= 1%; ties use the smaller FPR upper bound and then the higher threshold. For the cascade, candidate symmetric bands contain all validation scores within each unique absolute distance from the locked `Logistic-L1` threshold. Select the band with the fewest escalations whose cascade recall is at least `recall(transformer) - 0.02` and whose FPR bound is <= 1%; if none qualifies, record that the target was not met rather than changing the rule. Test outcomes cannot change these choices. |
| Shift monitoring | The primary monitor is a diagonal-covariance GMM fitted to standardized structural features plus the stage-1 score from PhiUSIIL training data. Component count is selected by BIC over 1-6. PhiUSIIL validation domains are divided by a frozen domain-hash rule into separate monitor-calibration and false-alert-audit streams. Windows contain 256 requests with stride 64 and are scored by mean negative log-likelihood. The alert boundary is the 95th percentile of calibration-window scores; false alerts are measured only on the independent audit stream. MMD and PSI are secondary comparators. |
| Shift streams | The primary shift is explicitly an external source/domain shift: PhishVN test URLs relative to the PhiUSIIL reference. This is not described as pure within-source temporal drift. Controlled string-only URL perturbations are sensitivity evidence for obfuscation shift and cannot satisfy H2. |
| Window manifest | The primary monitoring stream retains every PhishVN test record in its published order; confidence filtering occurs only after routing when error metrics are calculated on `gold`. The first 256 requests use the fixed cascade. Windows end at request 256 and every 64 requests thereafter. Each alert routes the next available 256 arrivals through the transformer; overlapping activations are unioned and a terminal activation is truncated at the end of the stream. The transformer is invoked at most once per request. Stream membership and denominators are frozen before outcomes are read. |
| Statistical analysis | Primary recall differences use a registrable-domain-clustered, 2,000-replicate percentile bootstrap with a 95% confidence interval. Resampling and paired predictions use seed `20260816`. Exact McNemar tests are secondary. Ablation-family p-values use Holm correction; neither analysis replaces a primary decision rule. |
| Validity controls | Before fitting, canonicalize the development data and quarantine invalid rows, exact duplicates, label conflicts, and cross-split domains without consulting outcomes. After written advisor approval and protocol freeze, an automated label-blind check may compare hashed test domains for overlap; it records exclusions without exposing labels or changing any model choice. Source-only, formatting-only, and label-permutation checks test for shortcut learning. Missing inputs stop the run; no synthetic or imputed replacement may enter confirmatory fitting. |
| Secondary reporting | Report average precision, recall at 1% FPR, precision, F2, MCC, balanced accuracy, ROC-AUC, Brier score, calibration error, and expected alerts and misses per 10,000 requests at assumed prevalence of 0.1%, 1%, and 5%. These measures describe the result but do not replace the locked hypothesis rules. |
| Operational replay | The primary benchmark manifest contains 10,000 PhiUSIIL group-test URLs at a declared 1% phishing prevalence, sampled by class without replacement with seed `20260816`; 0.1% and 5% prevalence manifests are sensitivity analyses, not estimates of gateway prevalence. H3 evaluates the fixed uncertainty cascade with drift monitoring held normal; drift-period routing and transformer-only worst-case load are reported separately. Real HTTP runs use concurrency 1, 8, 16, 32, 64, and 128, with 1,000 warm-ups and 10,000 measured requests in each of 5 runs. H3 evaluates latency and errors only at concurrency 64. The detailed replay protocol is committed and hashed before any test processing. |

## Decision Matrix

| Item | Proposed question and hypothesis | Method | Primary evidence | Decision rule |
|---|---|---|---|---|
| **RQ1 / H1** | **RQ1:** What incremental value do structural URL features and character-level representations provide under registrable-domain-disjoint and external evaluation? **H1:** At the validation-selected FPR ceiling, full structural features improve recall over a length-only baseline, and the character-transformer cascade improves recall over `Logistic-L1`. | Fit length-only, `Logistic-L1`, transformer-only, and cascade models on PhiUSIIL training data. Use validation data only for thresholds, early stopping, and the cascade band. Score the untouched PhiUSIIL group test and, after approval, PhishVN once without detection-model adaptation. | Paired predictions on the PhiUSIIL group test and PhishVN `gold`; PhishVN `all` and feature-family ablations are sensitivity evidence. | Support H1 only if each compared model has observed FPR <= 1% and, on both primary test sets, the domain-clustered 95% bootstrap lower bounds are greater than zero for `recall(Logistic-L1) - recall(length-only)` and `recall(cascade) - recall(Logistic-L1)`. |
| **RQ2 / H2** | **RQ2:** Can GMM-based monitoring detect an external source/domain shift and guide escalation without exceeding the low-FPR operating constraint? **H2:** GMM detects at least 80% of prespecified external shift windows at no more than 5% false alerts, and prospective routing reduces the false-negative rate relative to the fixed cascade while retaining FPR <= 1%. | Fit the GMM on PhiUSIIL training features, set its boundary on one validation stream, and measure false alerts on a separate validation audit stream. Apply it without labels to the full ordered PhishVN test stream. Each alert routes the next 256 requests through the transformer. MMD, PSI, and controlled perturbations are secondary. | Window alerts plus paired fixed-cascade and prospective-policy predictions. Error inference uses PhishVN `gold`; `all` remains sensitivity evidence. | Support H2 only if external-window detection is >= 80%, independent reference false alerts are <= 5%, alert-policy FPR is <= 1%, and the lower bound of a domain-clustered 95% bootstrap interval for the false-negative-rate reduction is greater than zero. |
| **RQ3 / H3** | **RQ3:** What detection, escalation, throughput, and latency tradeoffs determine whether the fixed cascade is viable inline? **H3:** At an observed external FPR of at most 1% for both systems, cascade recall is noninferior to transformer-only recall within 2 percentage points; on the 1%-prevalence benchmark reference, transformer invocation is at most 30%, real-HTTP p95 latency is at most 200 ms at concurrency 64, and errors are below 0.1%. | Compare the fixed cascade with transformer-only predictions on PhishVN at frozen thresholds. Replay the fixed cascade over real HTTP at the declared benchmark prevalence. Evaluate drift-period routing separately under H2. | Paired recall and FPR on PhishVN `gold`, the deterministic reference invocation trace, and five measured HTTP runs. Other prevalence and concurrency conditions are sensitivity evidence. | Support H3 only if both the fixed cascade and transformer-only observed PhishVN `gold` FPR are <= 1%, the 95% bootstrap lower bound for `recall(cascade) - recall(transformer-only)` is >= `-0.02`, stage 2 is invoked for <= 30% of the primary reference manifest, pooled p95 across all measured concurrency-64 requests is <= 200 ms, and errors are < 0.1%. |

The transformer and GMM remain central, while the earlier exploratory results are preserved but do not decide the new hypotheses. The title remains **Automated Phishing Detection for Frontier AI Inference**.

## Research Safeguards

- Evidence from the prior exploratory phase remains preserved but may not be used to accept or reject H1, H2, or H3.
- No URL is fetched. Only public data with a documented license may be used.
- If a required dataset, license, hash, label field, or split manifest is missing or inconsistent, the affected test stops and the hypothesis remains undecided. No imputed or synthetic dataset may replace it.
- Controlled URL perturbations are used only as declared monitoring probes; they do not replace labeled development or external evidence.
- Schema-invalid API requests retain the frozen FastAPI validation response and count as replay errors; they are not converted to phishing labels or silently removed from a denominator.
- Dataset hashes, row identifiers, split and window manifests, model artifacts, thresholds, software environment, and this protocol are frozen before any test is opened.
- License-compliant source archives, processed splits, licenses, data cards, and `SHA256SUMS` will be published in the repository's `datasets-v3.0.0` GitHub release; if a platform limit prevents a release asset, the manifest will record the licensed upstream archive and immutable checksum instead.
- Negative, null, or mixed outcomes are reported under the locked rules without test-informed retuning. The external test is not reused as validation data.
- The project title remains unchanged.
- Written advisor approval is required before any hypothesis-driven confirmatory experiment or access to the PhishVN test partition.
