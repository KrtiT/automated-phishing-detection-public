# Study-Only Execution Authorization

This implementation provides a separate whole-study route over the unchanged,
non-authorizing v3 binding. It is not an approval record or a research result.
Every legacy standalone entry and candidate readiness property remains closed.
The original [policy supplement](../data/study-execution-policy-v1.json) and the
separate [operator-authority policy](../data/study-execution-policy-v2.json) require
explicit adoption. Neither authorizes access merely by being committed.

## Review Before Access

The immutable private profile is constructed **after** the implementation commit
and exact-head verification. It binds:

- The exact revision and preserved v3 contract, committed policy and method hashes.
- The original external and operational candidate digests and the complete
  source/artifact hash scope from the unchanged base binding.
- Every canonical path in the original study CLI inventory, including source,
  model, preparation, source-output and operational-output destinations.
- One fixed root invocation, named operator and exclusive-session identifier.
- The policy's session requirements and prospective operator commitment to retain
  pre/post conditions, interference and thermal warnings.

Profile construction uses public metadata and lexical paths; it is not permission
to inspect protected source files, archives or models. The session declaration is
an obligation, not a claim that live host conditions have already been checked.

A separate original-v1 private envelope must contain actual method, advisor, exact-profile
and protected-access decisions. Final profile/access decisions reference the
immutable profile digest. Earlier method/advisor decisions retain their actual
method or policy scope; they are not rewritten as approval of a later revision.
Missing decisions, changed bytes or mismatched scope reject before protected path
inspection. No draft generator may invent an approving person or decision.

The complete envelope digest is supplied independently at invocation. The reviewed
command projection excludes only that envelope locator and digest, avoiding a
self-referential hash. The envelope remains private; only relevant decision
extracts belong in it, not full chats, credentials or unrelated material.

Decision records are trusted operator records, not cryptographic proof of consent.
Names, timestamps and an `approved` value alone do not establish human approval.

### Explicit Operator Authority

The separately versioned v2 route records an operator's instruction to proceed
without fresh advisor concurrence. It never fills the original `advisor` slot
with an invented approval and does not change v1 policy bytes or interpretation.
The original reviewed profile and its digest, named operator, verbatim directive
and actual recording time remain in the new private envelope. A technical-rebind
record identifies the recorder/time, directive digest and effective profile digest,
expressly states `governance_only`, and records that no advisor decision was obtained.

The four v2 decisions are method, advisor-requirement waiver, effective profile and
protected access. The three authorizations use `authorized_by_operator_directive`;
the waiver uses `waived_by_operator`. They retain the real operator/directive and
effective subject, not a claim that the operator personally inspected a later hash.
An advisor-approved substitute, missing directive, altered scope or mismatched
decision rejects. Paths, operator/session, v3 and scientific policy stay unchanged;
public source-scope changes are restricted to the fixed governance implementation.
Before sealing, the recorder independently audits the code diff, runtime and
scientific-artifact pins against the reviewed source scope.

This route supersedes only the project's advisor-concurrence prerequisite under
explicit operator instruction. It does not waive dataset licensing, an independently
applicable external obligation, frozen scientific rules or exclusive-session
conditions. It supplies neither advisor endorsement nor scientific results.

## One Fresh Study

`scripts/run_adopted_study.py` accepts only the reviewed repository/revision and
the sealed envelope locator/digest. It supplies no source, model, workload,
deadline, subset, resume or retry override. Its import-light `--help` performs no
protected read.

After admission, the root reserves fresh destinations and prepares both datasets
once. All thirteen existing necessary-capacity checks run before prediction. A
shortage retains a whole-study hold: both scoring workers and all 125 cells remain
unattempted. Malformed or changed preparation rejects instead of becoming a
population-shortage result. Passing capacity checks establishes necessary capacity,
not statistical adequacy or successful hypotheses.

The unchanged scientific owners then run in order: internal scoring, external
scoring, accepted-input retention, the fixed 125-cell program and original
reducers. The same parent accepts each source only after an observed successful
exit and verification of saved evidence. No synthetic PID, zero exit or accepted
state substitutes for a failed or unobserved launch.

The four fixed roles in `scripts/run_study_child.py` require live parent-owned
admission pipes. A copied envelope, marker file or environment string alone is
insufficient. Each bounded canonical frame joins the exact profile/envelope,
root reservation/intent, successful retained barrier, preparation, final command
and role-specific predecessor/cell identity. Only the read descriptor is inherited;
the parent retains its writer through owned child cleanup. Launch and exit
callbacks retain actual observations separately from frame issuance.

Children authenticate this channel before private inputs and recheck the study
supplement and channel at safe lifecycle boundaries. These checks are not
continuous revocation or protection against arbitrary malicious same-user code.
They add no per-record scoring or measured-request-loop checks.

## Evidence And Failure Handling

The distinct `adopted-study-root-v1` identity/intent/accounting wrapper retains the
original scientific records and a private authorization ledger. Existing
`study-root-v1` schemas are not loosened. Root inventories remain 10 files for a
hold and 14 for complete evidence; preparation, source and cell inventories are
unchanged. Scientific thresholds, populations, calculations and workloads do not
change. The original H2 audit remains 28/252, above its 5% limit.

Saved authorization checking requires independently supplied approved profile
and envelope hashes. It checks retained scope and observation joins, not consent,
historical process execution or new scientific performance. Original scientific
verification remains necessary.

Failures retain actual preparation/source progress, accepted cell prefixes,
unattempted suffixes and any returned-but-not-compacted candidate. Publication
guards remain permanent once publication starts. Nothing retries, resumes,
deletes an adverse attempt or enlarges protective deadlines automatically.

## Verification Limits

Tests use invented inputs. Genuine official child processes exercise profile,
pipe, root, retained-preparation and saved-output boundaries; synthetic model
sessions do not measure the accepted research models. Complete coordinator tests
construct source/cell observations to check all 125 positions and 252 admission
joins. They are not a completed 125-cell research execution.

The completion sequence remains: reviewed and verified implementation, complete
actual approvals, one authorized frozen execution, retained-evidence verification,
then RQ/H synthesis and manuscript/deck updates. A whole-study hold or successful
software test is not completion of the promised research questions.
